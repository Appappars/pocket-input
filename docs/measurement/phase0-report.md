# Протокол спайка фазы 0 (спека 05-roadmap-qa.md, п. 5.3.8)

Фаза 0: телефон регистрируется как Bluetooth HID-композит (клавиатура+мышь)
и управляет реальным Windows-ПК. Протокол фиксирует 6 пар «телефон × ПК»
из матрицы 5.5 (3 телефона × 2 ПК).

**Правило закрытия: фаза 0 НЕ закрывается, пока в таблице ниже хотя бы одна
строка пуста или помечена «не проверено». «Не проверено» — блокирующий статус
(матрица 5.5).**

## Шапка протокола (поля п. 5.3.8)

| Поле | Значение |
|---|---|
| Телефон | не проверено (ни один телефон матрицы ещё не подключался) |
| ПК | этот ПК: Windows 10, hostname `DESKTOP-P0HH887`; матричный слот «Windows 10, Realtek BT 4.0» — идентичность BT-адаптера не подтверждена |
| Вердикт по профилю `HID_DEVICE` | не проверено (нужен запуск `getProfileProxy(..., HID_DEVICE)` на телефоне) |
| Задержка первого клика после 60 с idle | не проверено |
| Скриншот диспетчера устройств | не проверено — файл `docs/measurement/devmgr-<дата>.png` не создан |

Реально получено на этом ПК (2026-11-17): `tools/hid_probe.py` перечислил
**12 HID-интерфейсов**, все видны системе («HID OK»), 3 интерфейса с
boot-протоколом (usage_page 0x01 + Report ID). Полный артефакт:
[`hid-probe-2026-11-17.md`](hid-probe-2026-11-17.md). Повторный запуск
воспроизводит таблицу (проверено двумя прогонами подряд).

## Что осталось сделать для закрытия фазы 0

1. Подключить каждый из 3 телефонов к каждому из 2 ПК, получить вердикт
   `getProfileProxy(..., HID_DEVICE) != null` (задача 5.3.3).
2. Снять движение курсора и ввод латиницы в Блокнот (задачи 5.3.5–6).
3. Замерить задержку первого клика после 60 с idle (норматив ≤ 50 мс, чек-лист п. 6).
4. Приложить скриншот диспетчера устройств с парой «телефон как HID-композит».
5. Прогнать `hid_probe.py` на втором ПК матрицы (Win11, Intel BT 5.2) и сохранить
   `docs/measurement/hid-probe-<дата>.md`.
