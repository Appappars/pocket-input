## Приложение Б. Глоссарий

Термины, без которых разделы 1–5 читаются двусмысленно. Порядок — по первому появлению в тексте.

| Термин | Значение в этом документе |
|---|---|
| **Транспорт A** | Ветка «чистый HID»: телефон регистрируется на ПК как Bluetooth-клавиатура и мышь через `BluetoothHidDevice` (Android 9+). Софт на ПК не нужен, Unicode и магнетизм недоступны |
| **Транспорт B** | Ветка «свой протокол + агент»: бинарные пакеты по RFCOMM поверх классического Bluetooth, инъекция через агент на Python. Даёт кириллицу, абсолютные координаты и магнетизм |
| **Агент** | Программа на ПК (`agent/pocketinput`), принимает пакеты, инжектирует ввод, притягивает курсор к элементам интерфейса, живёт в трее |
| **Пивот** (точка вращения) | Физическая точка, вокруг которой реально вращается телефон — запястье или локоть, не корпус телефона и не его торец. Сдвиг пивота — главный источник ошибки наведения |
| **Луч** | Полупрямая из середины верхнего торца телефона вдоль его длинной оси. Наведение — пересечение луча с плоскостью монитора |
| **Точка попадания** | Точка пересечения луча с плоскостью монитора в метрах или в пикселях экрана |
| **`H`** (гомография) | Матрица 3×3, отображающая направление луча в координаты экрана. 8 свободных параметров, определяются четырьмя касаниями углов. Хранится на телефоне |
| **`p_z`** | Оценка дистанции от пивота до плоскости монитора, извлекаемая из `H`. Нужна для контроля валидности калибровки (0.35–3.0 м) |
| **`err₅`** | Ошибка на контрольной (пятой) точке калибровки: насколько предсказание `H` расходится с реальным касанием центра экрана. Единственная честная метрика качества калибровки |
| **Резидуум (RMS)** | Среднеквадратичная невязка по четырём точкам калибровки. В этой системе **тождественно нулевая** (8 уравнений, 8 неизвестных) и потому бесполезна как контроль качества |
| **L0** | Уровень позиционирования «гомография по четырём касаниям». Точен, пока пивот не сдвинулся |
| **L1** | Уровень «перецентровка одним касанием»: одна точка с известными координатами даёт 2 уравнения на 2 неизвестных сдвига пивота |
| **L2** | Уровень «ARCore»: визуально-инерциальная одометрия даёт позицию и ориентацию (6DoF), маркеры — позу монитора. В v1 не входит, опция v1.1 |
| **L3** | Уровень «ZUPT»: краткая интеграция акселерометра с обнулением скорости в покое. Исследование, вне v1 |
| **ZUPT** | Zero-Velocity Update — приём из пешеходной навигации: пока акселерометр показывает покой, скорость принудительно обнуляется, и дрейф не накапливается |
| **VIO** | Visual-Inertial Odometry — совместная оценка позы по камере и инерциальным датчикам (основа ARCore) |
| **Augmented Images** | Функция ARCore: распознавание заранее заданных изображений и оценка их позы относительно телефона |
| **One Euro filter** | Адаптивный фильтр нижних частот для дрожащих сигналов: сильнее сглаживает в покое, слабее при быстром движении. Параметры — `minCutoff` (Гц) и `beta` |
| **Групповая задержка (τ)** | Задержка, которую фильтр вносит в сигнал: для фильтра первого порядка `τ = 1/(2π·fc)`. Это она, а не стоимость вычислений, определяет, насколько «тормозит» курсор |
| **`fc`** | Эффективная частота среза One Euro: `fc = minCutoff + beta·|ω|`, растёт со скоростью движения |
| **`gain`** | Коэффициент ускорения: во сколько раз приращение курсора больше приращения угла. `gain = 1 + a·k·(|ω|/ω_ref)^1.5` |
| **`acceleration`** | Пользовательская настройка 0…1 (по умолчанию 0.35), множитель `a` в формуле `gain` |
| **deadzone** | Мёртвая зона по угловой скорости (≈0.5 °/с): ниже неё курсор не двигается, чтобы не дрожал от шума гироскопа |
| **Магнетизм** | Притяжение курсора к ближайшему кликабельному элементу в радиусе 60 px. Реализуется на ПК, не на телефоне |
| **Якорь** | Точка с известными экранными координатами, которую пользователь касается при перецентровке. В ветке A — фиксированные 5 точек, в ветке B — метка, которую рисует агент |
| **UIA** | Windows UI Automation — интерфейс доступа к дереву элементов и их прямоугольникам. Источник целей для магнетизма |
| **CDP** | Chrome DevTools Protocol — источник прямоугольников элементов для браузера (`getBoundingClientRect`) |
| **DPI-awareness** | Режим процесса, при котором Windows не масштабирует координаты за приложение. Без `PER_MONITOR_AWARE_V2` абсолютные координаты уезжают при масштабе ≠ 100 % |
| **Виртуальный рабочий стол** | Объединённое координатное пространство всех мониторов. Начало — левый верхний угол основного; координаты могут быть отрицательными |
| **Digitizer HID** | Дополнительный HID-интерфейс «абсолютный указатель»: ПК получает абсолютные координаты без мышиного ускорения. В v1 — экспериментальный флаг |
| **Keystone** | Трапецеидальное искажение проектора. Прямоугольником не является, но `H` остаётся валидной — она не предполагает прямоугольника |
| **Sniff mode** | Энергосберегающий режим Bluetooth-соединения: первый пакет после паузы задерживается. Лечится no-op пакетом |
| **RFCOMM** | Профиль последовательного порта поверх классического Bluetooth; транспорт ветки B |
| **HOGP / BLE HID** | HID поверх BLE (Bluetooth Low Energy). В v1 не используется: интервал 15–30 мс ломает бюджет задержки указки |
| **`PKT_MAX`** | Максимальный размер обычного пакета (10 байт). Кадры аутентификации вынесены в отдельный класс `PKT_MAX_AUTH = 32` |
| **`seq`** | Порядковый номер пакета. Повтор идёт с тем же `seq`; получатель дедуплицирует по `last_delivered_seq` |
| **Деградация** | Автоматический переход на более слабый режим (HID → агент, магнетизм → без магнетизма, указка → трекпад) с явным сообщением пользователю, а не молчаливым ухудшением |
| **Уровни деградации (2.3)** | Четыре триггера: нет HID-профиля, нужен русский текст, нужен магнетизм, ручной выбор транспорта. Обратный переход — только вручную |
| **Allowlist** | Список устройств, которым разрешено управлять ПК: `id`, имя, дата пары, ключ, статус `active`/`revoked` |
| **Сессионный ключ** | 16 байт, выведенные из ключа устройства; на них строится HMAC-челлендж кадра аутентификации |
