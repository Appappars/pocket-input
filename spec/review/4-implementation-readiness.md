## Ревью EGM: Implementation Readiness

Ревьюер: `@rev-readiness` (роль EGM `implementation_readiness`, Mode: REVIEW). Документ не писал.
Проверено: `spec/PocketInput-SPEC.md`, 1904 строки, разделы 1–5 полностью.
База: `egm/resources/document_standards/implementation-readiness-standard.md` (zero-decision rule: «If the implementer must make design choices … the plan **fails** this standard»), `egm/agents/implementation_readiness.md`.

### Вердикт (PASS/FAIL по zero-decision rule, одна строка + причина)

**FAIL** — §5.3 заявляет «Реализацию внутри файла исполнитель не выбирает — она задана», но задачи 3, 4 и 6 фазы 0 оставляют исполнителю выбор источника HID-дескрипторов, способа регистрации композита и коэффициента трекпада; фаза 1 не имеет ни одной файловой задачи; а контракт протокола внутренне противоречив: аутентификация §2.7 не имеет кадров в таблице 14 типов §2.4, `recenter` с `dpx/dpy` int8 (±127 px, §2.4) не выражает сдвиг до 600 px (§3.5), `PKT_MAX = 10` (§2.4) исключает AES-GCM-пакет 22–26 байт (§2.7), а `AccelCurveTest` требует коэффициента ≥ 2.0 при 5 °/с (§5.4.1) там, где формула §3.7 даёт 1.265.

Счёт находок по таблицам: I — P0 9, P1 11, P2 1 (21); D — P0 1, P1 11, P2 4 (16); N — P0 1, P1 3, P2 3 (7); T — P0 1, P1 8, P2 2 (11); P — P0 2, P1 3, P2 2 (7).
