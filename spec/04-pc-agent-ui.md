## 4. Агент на ПК и интерфейс приложения

Агент на Windows — единственное место, где доступны Unicode-текст, магнетизм курсора, фокус и
диагностика; приложение — единственное место, где пользователь видит состояние и меняет параметры
без перезапуска. Бюджет без фильтра: сенсор → курсор ≤ 25 мс (IMU 5, транспорт 10–15, инъекция ~1);
с фильтром fast норматив P50 ≤ 60 мс, P95 ≤ 80 мс. Значит агенту от приёма байт до `SendInput`
остаётся 3–8 мс в зависимости от транспорта.

### 4.1 Агент: архитектура процесса

Один процесс Python без GUI-фреймворка: трей, YAML-конфиг, лог. Потоки разделены по трём несводимым
нагрузкам: сеть (блокирующее чтение), ввод (жёсткий дедлайн), опрос чужого интерфейса (дорого).

| Поток | Что делает | Частота | Блокирующие операции | Дедлайн |
|---|---|---|---|---|
| `rx` | приём, проверка заголовка/длины, распаковка | 60–120 Гц | `recv` | не терять пакеты |
| `decode` | версия, тип, оси, сборка кадров, дедупликация | 60–120 Гц | нет | ≤ 1 мс |
| `inject` | очередь → `SendInput`, sticky, текстовый буфер | по приходу | только Win32 | ≤ 1 мс |
| `finder` | снимок прямоугольников: UI Automation + CDP | 4–8 Гц | COM, HTTP | 120 мс на провайдер, иначе пропуск |
| `link` | соединение, handshake, реконнект, heartbeat | 1 Гц + события | `connect` | не критичен |
| `tray` (главный) | цикл сообщений, меню, уведомления | событийно | нет | — |

**`inject` — единственный владелец** курсора и клавиатуры. Иначе два источника переставляют курсор
в произвольном порядке, а вызовы из чужого потока дают рывки между кадрами.

```text
socket ─► [rx] ─queue.Queue(maxsize=32)─► [decode] ─► [inject] ─► SendInput
                                              ▲
[finder] ─ snapshot{rects, active_window, epoch} ┘   (магнетизм)
[tray]   ─ команды: старт/стоп/переподключить ─► [link]
```

**Почему инъекция не в UI-потоке.** Пока открыто контекстное меню или тост, поток трея занят
модальным циклом, и пакет, поставленный в него, ждёт закрытия меню — десятки и сотни миллисекунд,
то есть бюджет 25 мс разрушен. Отдельный поток от меню не зависит; трей получает только
уведомления о смене состояния.

**GIL.** Потоки не дают параллельного байткода, но `SendInput`, `recv` и COM-вызовы отпускают GIL
на время системного вызова. Проблема не в параллельности, а в джиттере: пока `finder` разбирает
дерево (200+ мс чистого Python), `inject` может не получить GIL вовремя. Меры по приоритету:

1. `sys.setswitchinterval(0.001)` — шаг принудительной отдачи GIL 1 мс вместо 5.
2. Горячий путь без аллокаций на пакет: структуры `INPUT` собраны один раз, меняются поля.
3. Обход дерева — в отдельный процесс (`multiprocessing`), наружу только готовый список
   прямоугольников: снимает GIL и риск зависания на чужом COM-объекте (процесс убивается по
   таймауту, инъекция продолжается).
4. Никаких `sleep` в горячем пути: `queue.get(timeout=…)` отпускает GIL.

**Модель отказа.** Очередь — `queue.Queue(maxsize=32)`. При переполнении вытесняется самый старый
`mouse_move*` (политика 2.2); события `key`, `mouse_btn` и `text_unicode` не вытесняются никогда.
`inject_queue_drops` идёт в лог, `degraded` — в приложение. После
сна агент пересоздаёт сокет, сбрасывает sticky и шлёт кадр пересинхронизации.

### 4.2 Инъекция ввода

Только `SendInput` (user32 через `ctypes`): единственный путь через ту же очередь ввода Windows,
что и физическая клавиатура, — событие видят хуки, его принимают игры на Raw Input, порядок с
курсором сохраняется.

Агент при старте вызывает `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`; при неудаче —
предупреждение в лог и режим только относительных дельт. Без этого на 125 % курсор встаёт на 20 %
левее цели.

| Что шлём | Событие | Когда | Почему так |
|---|---|---|---|
| клавиша по коду | `KEYEVENTF_SCANCODE` / виртуальный код | латиница, стрелки, F-клавиши, hotkeys | сохраняет автоповтор и работу игр |
| клавиша как символ | `KEYEVENTF_UNICODE` + UTF-16 код-юнит | кириллица, диакритика, CJK, эмодзи | не зависит от раскладки ПК |
| движение, относительный режим | `MOUSEEVENTF_MOVE`, `dx/dy` в физических пикселях | ветка A и ветка B без `mouse_abs` | абсолютная позиция ломает ускорение мыши пользователя |
| движение, абсолютный режим | `MOUSEEVENTF_ABSOLUTE` + `MOUSEEVENTF_VIRTUALDESK`; координаты нормируются в 0..65535 по габаритам виртуального рабочего стола (`x·65535/(W−1)`, `y·65535/(H−1)`) | только по пакету `mouse_abs` (0x07) | единственный путь в абсолютный режим 3.6; требует `PER_MONITOR_AWARE_V2` |
| клик | `LEFTDOWN/UP`, `RIGHTDOWN/UP`, `MIDDLEDOWN/UP`, `XDOWN/UP` | по кнопкам протокола | — |
| колесо | `MOUSEEVENTF_WHEEL`/`HWHEEL`, `WHEEL_DELTA=120` | скролл | дробные дельты накоплением |

**Почему HID ломает русский текст.** HID-клавиатура передаёт не символ, а usage code физической
клавиши, и ПК подставляет то, что этой клавише сопоставлено в *активной раскладке*. Обратного
канала «какая раскладка» у телефона нет. Дефекты: при раскладке «США» нажатие «ф» печатает `a`;
смена раскладки посреди слова делит его на два алфавита; при английской раскладке на ПК весь
русский текст уходит латиницей. Смена раскладки на ПК требует прав и ломает чужой ввод.

`KEYEVENTF_UNICODE` кладёт в `wScan` готовый UTF-16 код-юнит: Windows вставляет его в очередь
ввода, минуя раскладку. Ограничения: символы вне BMP идут суррогатной парой двумя событиями
подряд; программы с собственной обработкой `WM_KEYDOWN` (часть игр, консоли) могут Unicode-события
не понять — для них есть откат.

```python
def send_text(text: str) -> None:
    units = text.encode("utf-16-le")
    inputs = (INPUT * (len(units) // 2))()
    for i in range(0, len(units), 2):
        ev = inputs[i // 2]
        ev.type = INPUT_KEYBOARD
        ev.ki.wScan = units[i] | (units[i + 1] << 8)
        ev.ki.dwFlags = KEYEVENTF_UNICODE                  # нажатие
    send_inputs(inputs)                       # SendInput(n, inputs, sizeof(INPUT))
    for ev in inputs:                                     # те же юниты, отпускание
        ev.ki.dwFlags = KEYEVENTF_UNICODE | KEYEVENTF_KEYUP
    send_inputs(inputs)
```

**Fallback через буфер обмена.** Если окно не приняло Unicode-события (ни одного нового символа в
поле): сохранить текущий `CF_UNICODETEXT` → положить свой текст → отпустить модификаторы →
синтезировать `Ctrl+V` → подождать 120 мс → восстановить прежнее в `finally`, иначе пользователь
теряет буфер. Если буфер за это время изменило другое приложение, восстановление пропускается.
`OpenClipboard` может быть занят — 5 попыток по 20 мс. Поля, блокирующие вставку, не получат
ничего, и это сообщается, а не замалчивается.

**Модификаторы и sticky.** Состояние живёт на телефоне и передаётся в каждом пакете маской; агент
сравнивает её с текущей и генерирует только разницу — поток идемпотентен, при потере пакета
состояние сойдётся на следующем. Sticky (нажал-зафиксировал) целиком на телефоне: маска остаётся
взведённой. Агент обязан: отпустить `Shift`/`Ctrl`/`Alt`/`Win` перед Unicode-последовательностью
(модификатор искажает символ в приложениях, читающих состояние клавиатуры); сбросить модификаторы
при разрыве связи и после сна; не держать `Win` дольше 5 с, иначе система уходит в «Пуск».

Ctrl+клик и Shift+клик выражаются полем `mods` в `mouse_btn`; sticky-модификаторы — пакетом
`mods_set` (0x08).

**Куда инжектировать нельзя.** UIPI блокирует `SendInput` из процесса с низкой целостностью в
окно с более высокими правами: окно UAC, диспетчер задач, оснастки, редакторы «от имени
администратора». Вызов при этом **возвращает успех**, событие отбрасывается системой — худший
сценарий, когда пользователь печатает в пустоту.

| Шаг | Механизм | Что делаем |
|---|---|---|
| целевое окно | `GetForegroundWindow` + `GetWindowThreadProcessId` | знаем PID получателя |
| права | сравнение уровня целостности токена цели со своим | флаг `target_elevated` |
| результат | `SendInput` возвращает число принятых событий | меньше ожидаемого → отказ |
| сообщение | тост + статус `blocked_elevated` в приложение + лог | не чаще 1 раза в 10 с |

Текст для пользователя: «Активное окно запущено от имени администратора. Windows не позволяет
PocketInput вводить в него текст. Запустите агент от имени администратора, если нужно управлять
этим окном». UIPI не обходится — перезапуск с повышенными правами делает пользователь. Защищённый
ввод (экран блокировки, пароль UAC) не принимает инъекцию принципиально.

### 4.3 Магнетизм курсора

Числа раздела 3 (1° ≈ 33 px на 0.6 м, промах 160 px при сдвиге руки на 5 см): точность ограничена
геометрией, а не фильтром. Магнетизм меняет задачу — вместо «попасть в кнопку 24 px» достаточно
**подвести курсор на 60 px**, ошибка наведения растёт в 2.5 раза без изменения математики.

| Источник | Что даёт | Задержка | Ограничения |
|---|---|---|---|
| UI Automation (`uiautomation`, `pywinauto`) | дерево элементов любого приложения: `BoundingRectangle`, тип, `IsEnabled`, `IsOffscreen`, доступность Invoke | до 120 мс на снимок (таймаут провайдера — 120 мс) | игры на DirectX, часть Electron, Java, консоли дерева не отдают; большие деревья (браузер, IDE) обходятся дорого |
| Chrome DevTools Protocol | точные прямоугольники кликабельного в странице (`getBoundingClientRect`, hit-test) | 5–20 мс при поднятом соединении | нужен браузер с портом отладки; активное окно должно быть тем же браузером; кросс-iframe требует обхода фреймов |
| перечисление дочерних окон | прямоугольники кнопок в классических Win32-диалогах | 1–5 мс | в современных тулбарах почти ничего не даёт |
| анализ пикселей | — | — | **не используем**: «кликабельность» по картинке ненадёжна, ложное притяжение хуже промаха |

```text
snapshot():
    if active_window is browser and cdp_session alive:      # CDP приоритетнее
        rects, source = cdp.visible_clickable_rects(), "cdp"
    else:
        rects, source = uia.clickable_rects(active_window, budget_ms=120), "uia"
    keep: area >= 16*16 px, visible, enabled, inside active window (physical pixels)
    return Snapshot{rects, source, epoch, ts}
```

Таймаут провайдера UIA — ровно 120 мс на провайдер; при превышении магнетизм отключается до
следующего кадра, `snapshot_hz` остаётся как в 4.4.

Алгоритм притяжения (снимок обновляется в фоне и не блокирует инъекцию):

1. Курсор переводится в координаты снимка (per-monitor DPI; и снимок, и курсор — физические
   пиксели).
2. Кандидаты — расстояние до **ближайшей точки** прямоугольника ≤ 60 px (не до центра: у широкой
   кнопки центр далеко, когда курсор уже на её краю).
3. Вес `w = (1 − d/60)² · k_source · k_size · k_focus`: `k_source` 1.0 для CDP и 0.7 для UIA,
   `k_size` 1.4 для целей мельче 32×32 px, `k_focus` 1.5 для активного окна и 0.3 для прочих.
4. Максимум меньше 0.15 — притяжения нет: в пустом месте курсор не дёргается.
5. Смещается **дельта**, не позиция: `dx' = dx + α·(tx − x)`, `α = 0.35` за кадр, `t` — точка
   внутри прямоугольника не ближе 6 px от края. Инерция сохраняется: при выходе из радиуса курсор
   не «прыгает назад».
6. Подсветка: рамка 1 px отдельным прозрачным окном (`WS_EX_LAYERED | WS_EX_TRANSPARENT`) — фокус
   не забирает, в hit-test не участвует. Модуль подсветки — `agent/pocketinput/overlay/`.

**Конфликт соседних элементов.** При конфликте двух элементов в радиусе 60 px выигрывает тот, чей
прямоугольник ближе по Манхэттену И который принадлежит активному окну; при равенстве — элемент с
меньшей площадью. Прилипание к соседнему элементу в плотном списке (высота строки < 24 px)
отключается: если расстояние до второго кандидата меньше 12 px, магнетизм не применяется вообще.

Притяжение действует на движение, но не на клик: клик идёт туда, где курсор реально находится,
поэтому «нажал не туда» из-за запаздывания снимка невозможно. Снимок старше 1.5 с отключает
магнетизм; `Alt` подавляет его — нужен способ встать точно.

### 4.4 Трей и настройки агента

Иконка трея — единственный постоянный элемент агента; состояние кодируется цветом: серый — нет
связи, зелёный — активен, жёлтый — `degraded` (магнетизм недоступен, очередь переполнялась),
красный — отказ ввода (elevated-окно) или сокет потерян без автопереподключения.

| Пункт меню | Действие |
|---|---|
| «Подключено к Pixel 7» | текст состояния, не команда |
| Открыть диагностику | последние 200 строк лога и счётчики |
| Переподключить | переоткрыть сокет и handshake (когда не `active`) |
| Магнетизм курсора / Подсветка цели | вкл/выкл, сохраняется в конфиг |
| Запускать при входе | вкл/выкл (ветка `Run` текущего пользователя) |
| Открыть конфиг / папку логов | показать в редакторе / проводнике |
| Копировать сводку | версия, ОС, транспорт, счётчики, ошибки в буфер |
| О программе / Проверить обновления | версия и канал |
| Выход | остановить потоки, освободить сокет, снять иконку |

Конфиг — `%APPDATA%\PocketInput\agent.yaml`; перечитывается при изменении mtime (раз в 2 с) и
применяется без перезапуска, кроме полей с пометкой `restart`. При синтаксической ошибке старый
конфиг остаётся в силе, в трее появляется жёлтый маркер, в лог идёт номер строки.

```yaml
version: 1
transport:
  mode: rfcomm                 # rfcomm | ble            restart
  rfcomm:
    channel: 4                 # 1..30, согласуется при handshake
  ble:
    service_uuid: "0000f0a0-0000-1000-8000-00805f9b34fb"
    reconnect_backoff_s: [0.5, 1, 2, 4, 8]   # последняя задержка повторяется
  # tcp: вне v1. Wi-Fi-транспорт потребует отдельного кадра с другим PKT_MAX
  # (AES-GCM делает пакет 22-26 байт), поэтому в v1 его нет и ключа в конфиге нет.
input:
  inject_method: auto          # auto | unicode | clipboard
  pointer_speed: 1.0           # 0.2..4.0
  acceleration: 0.35           # 0..1, вклад скорости в дельту
  sticky_timeout_s: 8          # автоотпускание зажатого модификатора
  text_chunk: 16               # символов на один SendInput-вызов
cursor:
  magnetism: true
  radius_px: 60                # 20..120
  strength: 0.35               # 0.05..0.8
  highlight: true
  sources: [cdp, uia]
  snapshot_hz: 6               # 2..8
  suppress_modifier: alt
logging:
  level: info                  # error | warn | info | debug
  max_bytes: 1048576           # ротация при 1 МБ
  backups: 5
security:
  allowlist_only: true         # принимать только сохранённые устройства
  idle_lock_s: 600             # блокировка ввода при простое, 60..3600
devices:                       # allowlist (2.7): принимаются только эти устройства
  - id: "a1b2c3d4"             # hex, 8 символов
    name: "Pixel 7"
    paired_at: "2026-11-17T18:00:00Z"   # ISO 8601
    key: "MDEyMzQ1Njc4OWFiY2RlZg=="     # base64, 16 байт
    status: active             # active | revoked
```

Логи: `%LOCALAPPDATA%\PocketInput\logs\agent.log`, формат «время ISO, уровень, поток, событие,
поля», ротация по размеру (1 МБ, 5 архивов, ≤ 6 МБ). Пишутся только события: старт/стоп, смена
состояния, подключение и отключение устройства, ошибки инъекции, отказы UIPI, счётчики раз в 60 с.
**Символы текста в лог не попадают** — только количество, иначе лог становится утечкой паролей.
Обновление: проверка раз в 24 ч и по команде, подпись до распаковки, установка при выходе,
предыдущая версия сохраняется для отката; автообновление по умолчанию выключено. Модуль
обновления — `agent/pocketinput/update/` (проверка подписи до распаковки, предыдущая версия в
`%APPDATA%\PocketInput\versions\`).

| Код выхода | Значение | Поведение оболочки автозапуска |
|---|---|---|
| 0 | нормальный выход по команде | не перезапускать |
| 3 | канал/порт занят другим экземпляром | поднять окно существующего |
| 4 | нет прав на инъекцию (политика, античит) | показать инструкцию |
| 5 | необработанное исключение в горячем потоке | перезапустить один раз, затем стоп |
| 6 | установлено обновление | перезапустить |

### 4.5 Экраны приложения

Шесть экранов в одном `NavHost`, переходы без анимации (она добавляет 200–300 мс латентности),
цели ≥ 48 dp. Связь видна везде: точка в заголовке и p50; при потере связи интерфейс не
блокируется, ввод не отправляется.

| Экран | Назначение и элементы | empty | loading | error | при потере связи |
|---|---|---|---|---|---|
| Подключение | выбор транспорта и устройства: переключатель HID/Агент, сохранённые устройства, «Найти», статус профиля HID и агента | «Нет сохранённых устройств — включите Bluetooth на ПК и нажмите Найти» | скелетоны 300 мс, таймаут поиска 10 с | текст ошибки + действие (включить BT, дать разрешение, переустановить агент) | баннер сверху, поле ввода дизейблится |

### 4.5.1 Индикатор канала и экран «Качество связи»

На экранах трекпада и клавиатуры сверху висит одна строка состояния канала: цветная точка + текст,
тап открывает экран диагностики. Состояния берутся из колбэков `BluetoothHidDevice`, а не из догадок:

| Состояние | Точка | Текст |
|---|---|---|
| `CONNECTED` | зелёная / жёлтая / красная по качеству | «Подключено · N%» |
| `REGISTERED` | жёлтая | «Нет связи — ПК не подключён» |
| `INIT` | жёлтая | «Подключаюсь…» |
| `NO_PROFILE` | красная | «Профиль HID недоступен» |
| `FAILED` | красная | «Регистрация HID не удалась» |
| `NO_ADAPTER` | красная | «Bluetooth недоступен» |

**Качество — не уровень сигнала.** RSSI классического Bluetooth-HID Android приложению не отдаёт
(`BluetoothDevice` не имеет `readRemoteRssi()` для BR/EDR, а `BluetoothGatt` относится к BLE).
Поэтому считается пригодность канала:

* задержка постановки отчёта в очередь отправки (p50 из окна 64 замеров): до 8 мс — без штрафа,
  далее линейно до −45 баллов к 40 мс;
* доля неудачных `sendReport`: до −30 баллов;
* число разрывов за сессию: по −7, не больше −20.

Итог — 0..100 баллов: ≥85 «хорошо», ≥55 «средне», ниже «плохо», при отсутствии связи — «не измерено».
Экран диагностики показывает все сырые числа, кнопку «Проверить канал» (ставит пустой отчёт в очередь)
и honest-примечание, что HID не подтверждает доставку. Формула — `LinkQuality` (покрыта тестом).

### 4.7 Клавиатура и текст

| | HID-путь | Путь через агент |
|---|---|---|
| что передаётся | usage-коды клавиш | UTF-16 код-юниты (`KEYEVENTF_UNICODE`) |
| зависимость от раскладки ПК | полная | нет |
| кириллица | только при русской раскладке на ПК, иначе латиница | всегда |
| латиница и hotkeys | нативно, включая игры и Alt+Tab | работает; игры с прямым опросом клавиш могут не увидеть |
| автоповтор | системный | таймер на телефоне |
| BIOS / UAC | да | нет |

Правило: **HID не позиционируется как средство набора русского текста.** При активном HID и
русской раскладке на телефоне показывается постоянная подсказка «Кириллица требует режима агента
или русской раскладки на ПК» с предложением переключиться. Молча печатать латиницу вместо
русского недопустимо.

Клавиатура приложения — **системная IME телефона**, а не собственная раскладка (решение владельца
продукта, 18.11.2026: свою клавиатуру в реальном использовании неудобно — нет свайпа, автокоррекции
и привычных языков). Реализация: невидимое поле ввода держит фокус и вызывает IME; изменения текста
диффятся (сколько удалено → Backspace, что вставлено → по одному usage-коду через таблицу символов),
поэтому работает и посимвольный набор, и вставка слова автокоррекцией, и удаление слова.

Символ → HID: латиница и пунктуация по раскладке US, кириллица — по позициям клавиш стандартной
русской раскладки Windows (ЙЦУКЕН на физической US-клавиатуре), заглавные — с `LSHIFT`.
Символы вне клавиатуры ПК (эмодзи, CJK) в HID-ветке не выражаются и считаются пропущенными —
это ограничение, которое снимает только путь через агент (фаза 2).

Что остаётся на панели приложения (IME этого не умеет): sticky-модификаторы Ctrl/Shift/Alt/Win,
Esc, Tab, Del, Backspace и стрелки. Автоповтор — системный (клавиша держится, повторяет ОС ПК).
Окно объявлено `windowSoftInputMode="adjustResize"`, поэтому панель всегда видна над IME.

Предсказуемый ввод: порядок символов строгий, буфер уходит пачками по `input.text_chunk`
(16 символов) одной `SendInput`-последовательностью; автоповтор при Unicode-пути — таймер на
телефоне (500 мс до первого повтора, далее 33 мс = 30 симв/с, стоп при отпускании или уходе в
фон); модификатор действует на следующий символ и сбрасывается после него, кроме sticky; локальный
предпросмотр показывает ровно то, что уйдёт, включая невидимые символы.

Вставка: «Вставить» отправляет буфер обмена телефона через clipboard-fallback агента. «Скопировать
с ПК» недоступна — обратного канала для объёмов протокол v1 не имеет. Пропускная способность
текста — ≈1.5 КБ/с на проводе (2 кодовые единицы на пакет, 312 пакетов/с); для вставки объёмом
> 1 КБ используется clipboard-fallback. Граница чанка задаётся битом `chunk_flags` в `text_unicode`
(2.4).

### 4.9 Доступность и эргономика

| Барьер | Решение | Проверяемый критерий |
|---|---|---|
| промах рукой | магнетизм 60 px, цели ≥ 48 dp, sticky drag | клик по кнопке 32 px при промахе 60 px успешен |
| тремор рук | deadzone до 3 °/с, повышенное сглаживание, удержание курсора (стоит, пока палец не сдвинулся на 20 px) | дрожание 0.3° не двигает курсор |
| работа одной рукой | основные действия в нижней трети экрана | ни одно действие не требует двух рук |
| работа лёжа | нет зависимости от ориентации, нет шагов «потрясите телефон» | в горизонтальной ориентации доступно всё |
| слабое зрение | контраст ≥ 4.5:1, масштаб до 200 %, тёмная тема | при 200 % текст не обрезается |
| нет вибро | подтверждения дублируются визуально (вспышка, точка в заголовке) | состояние понятно без тактильного канала |
| чувствительность к миганию | индикаторы обновляются ≤ 2 Гц | нет мерцаний > 3 Гц |

Вибро-отклик: импульс 10 мс на клик, двойной на захват магнетизмом, и **ничего** на движение
курсора — постоянная вибрация при наведении утомляет и разряжает батарею. Тёмная тема не
оформление, а требование: экран телефона в тёмной комнате рядом с монитором не должен слепить
(фон `#0E0E11`, один акцент, контраст текста проверяется на каждом экране).
