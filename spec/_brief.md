## Что это

**PocketInput** — Android-приложение, превращающее телефон в Bluetooth-клавиатуру и мышь для ПК
плюс в «лазерную указку» по экрану монитора на гироскопе. Два режима работы: обычный
(трекпад + клавиатура) и указка (наводишь телефон на экран, курсор идёт за верхним торцом,
тап = клик).

## Зафиксированные решения

### Транспорты (оба, за одним интерфейсом `Transport`)

| | **A. Чистый HID** | **B. Свой протокол + агент на ПК** |
|---|---|---|
| Как | Android `BluetoothHidDevice` (API 28+), телефон регистрируется как HID-композит клавиатура+мышь | бинарный протокол по RFCOMM (классический BT), fallback BLE GATT (`bleak`), опционально Wi-Fi TCP |
| ПК | драйверов не нужно, работает в BIOS/UAC/играх | нужен агент (Python, трей) |
| Ограничения | Unicode нельзя, логики нет, часть OEM не отдаёт профиль | нужна установка |

- iOS **вне scope v1** (нет публичного API быть HID-устройством).
- Референс для форка: `ToxicOrca/ghostboard-android-bluetooth-mouse-keyboard` (MIT, Kotlin) —
  композитные дескрипторы, трекпад, sticky-модификаторы, idle wake-up.
- Проверка профиля: `adapter.getProfileProxy(ctx, cb, BluetoothProfile.HID_DEVICE)`; null → деградация на B.

### Указатель (математика уже проверена, не переизобретать)

- Луч выходит из **середины верхнего торца** телефона, направление = длинная ось телефона.
- Уровни: **L0** гомография; **L1** одно касание = перецентровка; **L2** ARCore VIO + Augmented
  Images; **L3** ZUPT-интеграл акселерометра между касаниями.
- **L0:** касание четырёх углов монитора даёт 4 соответствия «направление луча → точка экрана» =
  8 уравнений. Отображение «луч → экран» имеет ровно 8 параметров (гомография, DLT + Гаусс),
  решение точное, резидуум ≈ 0.0000 px.
- **L1:** сдвиг пивота на (Δx, Δy) смещает точку попадания ровно на (Δx, Δy) → **одно касание
  любого угла = 2 уравнения на 2 неизвестных**, мгновенная перецентровка без полной калибровки.
- **Что физически невозможно (говорить прямо):** акселерометр даёт гравитацию, не позицию.
  Ошибка ориентации 1° утекает в гравитацию (0.17 м/с²) → 8 см дрейфа за 1 с, 34 см за 2 с.
  При чистом вращении масштаб (расстояние до монитора) ненаблюдаем — «метрический 3D-объём»
  из IMU не строится. Барометр/«уровень над морем» не помогает: ±10–100 см дрейфа, у ПК нет
  отсчёта высоты, высота не входит в пересечение луча с плоскостью.
- **Крен (roll) не двигает точку попадания** — луч выходит из торца, вращение вокруг луча
  ничего не меняет. Не тратить UX на крен.
- Реальный пивот — запястье/локоть, не торец: калиброваться в одной стойке, не переносить локоть
  между касаниями, иначе ошибка максимальна по краям экрана.
- **Числа для любых утверждений:** экран 1920 px, дистанция 0.6 м → 3200 px/м, **1° ≈ 33 px**.
  Проверено в демке: сдвиг руки 5 см → 160 px промаха, 10 см → 345 px, 14 см → 501 px;
  при ARCore 6DoF промах 0 px при любом сдвиге.

### Сенсоры и фильтрация

- `TYPE_GAME_ROTATION_VECTOR` (fused, **без магнитометра** — врёт рядом с монитором/колонками),
  регистрация 100–200 Гц; выше 200 Гц нужен `HIGH_SAMPLING_RATE_SENSORS` (Android 12+);
  `SENSOR_DELAY_GAME` (~50 Гц) слишком грубо.
- One Euro filter (стартовые параметры minCutoff 1.0, beta 0.007) + deadzone ~0.5°/с + кривая
  ускорения (медленно = точно, быстро = далеко). Сырой гироскоп даёт дрожащий курсор.

### ПК-агент

- Инъекция: `SendInput` через `ctypes`, для кириллицы `KEYEVENTF_UNICODE` (HID шлёт usage-коды и
  зависит от раскладки ПК — это главный баг чистого HID для русского текста), fallback — буфер обмена.
- Магнетизм курсора: прямоугольники кликабельных элементов из Windows UI Automation
  (`uiautomation`/`pywinauto`) и из Chrome DevTools Protocol (`getBoundingClientRect` для браузера),
  притяжение к ближайшему элементу в радиусе ~60 px с подсветкой.
- Трей-приложение, автозапуск, конфиг YAML, логи, автопереподключение.
- Ограничение: инъекция не работает в окна с более высокими правами (UAC/elevated) — описать и
  дать понятное сообщение, не «молча не работает».

### Протокол

- Бинарные пакеты 6–10 байт, первый байт — версия, затем тип, оси int8/int16, кнопки, флаги.
- 60–120 Гц, отдельный поток отправки (не UI), троттлинг, no-op пакет после паузы
  (Bluetooth sniff mode иначе съедает первый клик).
- Состояния: `idle → discovering → connected → handshake → calibrating → active → degraded`;
  реконнект по последнему устройству, буферизация при потере.

### Безопасность

- Паринг BT с PIN, allowlist сохранённых устройств, отказ от открытых LAN-портов по умолчанию,
  ключ сессии для Wi-Fi-канала, блокировка ввода при простое, явный индикатор «кто управляет ПК».

### Бюджет латентности

сенсор → курсор ≤ 25 мс: IMU-событие ~5 мс, фильтр ~2 мс, транспорт 10–15 мс (классический BT HID
интервал 7.5–15 мс), инъекция ~1 мс. Указать точки, где бюджет ломается.

### Приложение

- Kotlin + Jetpack Compose, foreground service, `BLUETOOTH_CONNECT` (Android 12+), `POST_NOTIFICATIONS`.
- Экраны: подключение, трекпад, клавиатура, указка (калибровка + наведение), настройки, диагностика.
- История продукта и остальное — на усмотрение автора раздела.
