# Как проверить Pocket Input 0.3.4

Установите `dist/PocketInput-0.3.4-hold-drag.apk` и сверяйте версию
`0.3.4-hold-drag` (код версии 12) в сведениях о приложении Android.
Для ручной приёмки нужны телефон Android и ПК Windows с Bluetooth.

1. На чистой установке нажмите «Разрешить Bluetooth». Сначала отклоните запрос.
   Приложение остаётся на экране подключения и предлагает выдать доступ.
   Выдайте его через системный диалог или настройки приложения.
2. Откройте настройки Bluetooth телефона. В настройках Bluetooth Windows добавьте
   телефон как устройство. Дождитесь подключения. Экран трекпада откроется
   после подтверждения HID-сеанса.
3. Запишите модели телефона и ПК, версии ОС, версию APK и итог каждого сценария.
   При разрыве приложите время и причины переходов из диагностики. Диагностика
   показывает состояние Bluetooth и результаты отправки на телефоне.

| Сценарий | Ожидаемый результат |
|---|---|
| Один тап и два быстрых тапа | Один тап сразу кликает. Два тапа доходят до Windows как два клика. |
| Захват за заголовок окна | Нажмите «Зажать ЛКМ», переместите окно и отпустите захват. Размер окна сохраняется. |
| Удержание с движением | Придержите палец на трекпаде и потяните. Окно движется с первого сдвига. Отпускание или отмена освобождает ЛКМ. |
| Долгое удержание на месте | Правый клик происходит при отпускании пальца. |
| Скролл сразу после тапа | Два пальца прокручивают колесо. После отпускания одного пальца курсор остаётся на месте. Базовый масштаб около одного деления на 20 dp. |
| Поворот и блокировка телефона | Активный сеанс принадлежит сервису. После возврата ввод продолжается, удержания сброшены. |
| Bluetooth выключен или Windows спит | Видна причина перехода. После включения Bluetooth или пробуждения приложение возвращает связь с известным ПК либо предлагает восстановление. |
| Явная остановка | «Остановить управление» завершает сеанс. Поворот не запускает его снова. Повторный запуск доступен на экране подключения. |
| Разрыв при захвате ЛКМ или при отправке Ctrl-комбинации | После восстановления кнопки и модификаторы отпущены, проходит только новый ввод. |
| Посимвольный ввод | Наберите слово без пробела. Каждая буква сразу появляется в Блокноте. Следующий пробел добавляется один раз. |
| Правка слова | Наберите «кот». В поле «Текст для ПК» выделите «о» и замените на «и». На ПК получается «кит», буква «т» сохраняется во время правки. |
| Раскладки и знаки | Сверьте «ПК · RU» с индикатором Windows. В панели «Знаки» отправьте `?`, `:`, `;` и `№`. Переключите раскладку через Win+Пробел, сверяйте EN и отправьте `@`. |
| Удаление неподдерживаемого символа | В EN наберите `a🙂`, удалите эмодзи клавишей телефона. Буква `a` сохраняется. Отдельно проверьте Enter и прямой Backspace. |
| Вставка и клик в соседнее поле | Хвост вставки остаётся в исходном поле, движение курсора доступно во время отправки. |
| Диагностика | Пробный отчёт показывает результат вызова Android. История отличает потерю ПК, регистрации и профиля. |

Автоматические проверки в каталоге `android/`:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

Метаданные APK проверяются через `aapt dump badging`. Результаты эмулятора
и приёмки на физическом Windows-ПК записывайте отдельно.

# Архив проверки 0.1.0-phase0

Файл APK: `dist/PocketInput-0.1.0-phase0.apk` (24,3 МБ, debug-подпись, `minSdk 28`, `targetSdk 34`).

Это **спайк**, а не продукт: цель — доказать или опровергнуть три вещи на живом железе.
Всё остальное (клавиатура, жесты, указка, магнетизм) появится в фазах 1–4.

| Что проверяем | Где смотреть |
|---|---|
| Отдаёт ли прошивка телефона профиль `HID_DEVICE` | строка «HID-профиль: доступен / недоступен» |
| Регистрируется ли HID-композит на реальном стеке | строка «Состояние HID: …» |
| Работает ли мышь на реальном Windows и как быстро после паузы | движение курсора, тап, задержка первого клика |

## 1. Поставить APK

1. Перекинуть файл на телефон: по USB (MTP), в Telegram «Избранное», на Google Drive — любым способом.
2. Открыть файл в проводнике телефона → «Установить».
3. Android спросит про установку из неизвестных источников — разрешить **для этого приложения** (Проводник / Telegram).
4. Если Play Protect ругается («приложение не проверено») — «Всё равно установить»: сборка debug, не подписана ключом Play.
5. Android 13+: при первом запуске разрешить **уведомления** (нужны для foreground-сервиса). Отказ не ломает приложение, но сервис перестанет быть foreground.
6. Первый запуск: Android 12+ спросит **«Разрешить PocketInput доступ к устройствам поблизости?»** — разрешить обязательно (это `BLUETOOTH_CONNECT`), без него список устройств пустой.

Требования: Android 9+ и Bluetooth. Wi-Fi не нужен.

## 2. Спарить телефон с ПК

Порядок важен: **парим со стороны ПК**, приложение только регистрирует себя как HID-устройство.

1. На телефоне: включить Bluetooth.
2. В приложении нажать **«Настройки Bluetooth — сделать телефон видимым»** → в настройках Bluetooth включить видимость («Видим для других устройств» / «Make discoverable»). Экран настроек придётся открыть ещё раз, если видимость отключилась через 2 минуты.
3. На ПК: **Параметры → Bluetooth и устройства → Добавить устройство → Bluetooth**.
4. В списке выбрать телефон. Windows спросит код — сверить его на телефоне и на ПК, подтвердить.
5. Вернуться в приложение. В списке появится строка с именем ПК → выбрать её.
6. Нажать **«Подключить»**. Кнопка открывает экран трекпада.

**Важно:** кнопка «Подключить» в этой сборке только переключает экран — она ничего не соединяет. HID-канал поднимает **Windows**: после спарки телефон появляется в списке как устройство ввода, и Windows подключает его сама.

Если через 10–15 секунд после спарки курсор не двигается: Параметры → Bluetooth и устройства → найти телефон в списке → «Подключить» (или удалить устройство и спарить заново).

## 3. Что именно проверить и что записать

Пять пунктов. По каждому — вердикт «да / нет / как именно сломалось».

### 3.1 Профиль HID (главный вопрос фазы 0)

Экран подключения, карточка статуса. Ожидаемо: «HID-профиль: доступен».
Если «недоступен» — **это тоже результат**, и очень важный: значит прошивка не отдаёт профиль
`HID_DEVICE`, и для этого телефона нужен ПК-агент (транспорт B). Записать модель и версию прошивки.

### 3.2 Регистрация HID-композита

Строка «Состояние HID: …». Значения:

| Значение | Что значит |
|---|---|
| `registered` | `registerApp` вернул `true` и система подтвердила регистрацию — **успех** |
| `register-failed` | профиль есть, но регистрация отклонена — записать модель телефона и прошивку |
| `no-profile` | профиль не выдан (то же, что «недоступен») |
| `connected` | ПК подключился, канал живой — **то, что нужно для пункта 3.3** |
| `proxy-lost` | система отобрала профиль (редко, но бывает при агрессивной экономии батареи) |

### 3.3 Курсор и клик

1. Открыть трекпад (кнопка «Подключить»).
2. Водить пальцем по серой области — курсор на ПК должен двигаться.
3. Тап (короткое касание без сдвига) — левый клик на ПК.
4. Проверить клик на чём-то видимом: открыть Блокнот, тапнуть в поле — появится курсор ввода.

Что записать: двигается ли плавно, есть ли рывки, «уезжает» ли курсор после остановки пальца,
работает ли тап с первого раза.

### 3.4 Задержка первого клика после простоя (норматив ≤ 50 мс)

Bluetooth переходит в энергосберегающий режим, и первый пакет после паузы иногда «съедается».
Проверка: оставить телефон и ПК в покое на **60 секунд**, затем сделать первый тап.
Если клик сработал сразу — норматив выполнен. Если первый тап пропал, а второй сработал — **дефект**
(в спеке лечится no-op пакетом после паузы, 2.6); записать «первый клик после 60 с пропал».

### 3.5 Диспетчер устройств Windows (скриншот)

На ПК: `Win+X` → Диспетчер устройств. Найти телефон в трёх местах:

- «Клавиатуры» — должно появиться HID-устройство клавиатуры;
- «Мыши и иные указывающие устройства» — HID-совместимая мышь;
- «Bluetooth» — сам телефон.

Сделать скриншот (Win+Shift+S), сохранить как `docs/measurement/devmgr-<дата>.png`.
Это доказательство, что Windows увидела **композит** «клавиатура + мышь», а не непонятное устройство.

### 3.6 Латиница в Блокнот — в этой сборке НЕ проверяется

Экрана клавиатуры в фазе 0 нет: только трекпад и тап. Ничего не сломано, это следующий шаг (фаза 1).
Ячейку «Латиница в Блокнот» в протоколе оставить «не проверено» до фазы 1.

## 4. Что прислать обратно

Минимальный набор, чтобы я закрыл строку матрицы:

1. Модель телефона, версия Android, версия прошивки (Настройки → О телефоне).
2. Что показала карточка статуса: обе строки + «Состояние HID».
3. Вердикты по 3.3 и 3.4 (двигается / клик / первый клик после паузы).
4. Скриншот экрана подключения (кнопки питания + громкость вниз, или как удобно).
5. Скриншот диспетчера устройств с телефоном.
6. Модель ПК и Bluetooth-адаптера (Диспетчер устройств → Bluetooth).

Если что-то не работает и хочется точную причину — с телефона по USB:

```bash
adb logcat -c && adb logcat -s PocketInputHID:* | head -40
```

Там видно `registerApp result: true/false`, `onAppStatusChanged: registered=…`,
`onConnectionStateChanged: state=…`, `sendReport failed`.

## 5. Диагностика: что означает каждая поломка

| Симптом | Причина | Что делать |
|---|---|---|
| «HID-профиль: недоступен» | прошивка не отдаёт `HID_DEVICE` (частая история у некоторых OEM) | записать модель; для этого телефона нужен транспорт B (агент на ПК) — это не баг приложения |
| «Состояние HID: register-failed» | система отклонила регистрацию | записать модель + прошивку, попробовать перезапустить приложение |
| `registered`, но курсор не двигается | Windows не подняла HID-канал после спарки | в Параметры → Bluetooth найти телефон → «Подключить»; проверить, что он виден как клавиатура/мышь |
| Курсор двигается, но рывками | слабый BT-адаптер или далёкое расстояние | проверить на расстоянии < 1 м, записать модель адаптера |
| Курсор «уезжает» сам | накопление мелких дельт при медленном движении | записать как дефект фазы 1 (нужен фильтр/порог) |
| Тап не срабатывает | сдвиг пальца > 8 dp распознаётся как drag | тапать коротко и без смещения |
| Устройства нет в диспетчере | спарка прошла без SDP-записи HID | удалить устройство на ПК, спарить заново при запущенном приложении |
| Приложение падает при старте | нет разрешения «Устройства поблизости» | Настройки → Приложения → PocketInput → Разрешения → разрешить |

## 6. Как это закроет фазу 0

Протокол: `docs/measurement/phase0-report.md`, матрица 3 телефона × 2 ПК = 6 строк.
Строка закрывается, когда в ней заполнены: профиль `HID_DEVICE`, движение курсора, латиница
(до фазы 1 — «не проверено»), задержка первого клика, скриншот диспетчера.

Правило из спеки: фаза 0 не закрывается, пока хотя бы одна строка «не проверено».
Достаточно начать с одной пары «этот ПК + твой телефон» — это уже 2 из 6 строк.

## 7. История сборок

| Версия | Что изменилось |
|---|---|
| `0.1.0-phase0` | первая тестовая сборка: спайк HID, трекпад, видимый статус, кнопка настроек BT |
| `0.1.1-tapfix` | **исправлен тап.** `detectDragGestures` не вызывал ни `onDragStart`, ни `onDragEnd` без превышения touch slop, поэтому чистое касание до клика не доходило вообще. Касание переведено на один цикл `awaitEachGesture`; клик отправляется как нажатие → пауза 40 мс → отпускание (Windows иногда склеивает фронт и спад из одного кадра) |

## 8. Ограничения этой сборки (чтобы не искать несуществующее)

- нет экрана клавиатуры и ввода текста;
- нет скролла двумя пальцами, нет правой кнопки;
- кнопка «Подключить» не соединяет, а только открывает трекпад;
- тап = клик, но **перетаскивание с зажатой кнопкой не работает**: drag отправляет только движение без кнопки. Перетаскивание окон и выделение мышью — фаза 1;
- правой кнопки и колеса нет;
- тема — стандартная Material 3, дизайна нет (фаза 1);
- debug-подпись: играть в игры с античитом не стоит, HID там детектится;
- уведомление может быть пустым — канал уведомлений сделан заглушкой в фазе 0.
